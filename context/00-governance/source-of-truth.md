# Jerarquía de fuentes y resolución de conflictos

1. Requisitos/decisiones explícitos más recientes del usuario: Flutter Web **Provider**, NestJS, PostgreSQL; modelo mixto; disponibilidad automática con restricciones por solicitud.
2. Documento técnico `InkSlot_Especificacion_Tecnica_MVP_v1.0.pdf`: negocio, RF-01..19, RD-01..12, AC-01..10 y arquitectura funcional.
3. `InkSlot_Prototipo.zip`: composición visual, nombres de pantallas, colores, tipografías, assets, estados, interacciones y animaciones reales. Leer `README.md` y `design-tokens/tokens.json`.
4. `InkSlot_Prototipo.html`: ejecutable autocontenido, útil como comparación complementaria.
5. Este SDD: formaliza contratos y propone decisiones de implementación. Las propuestas nuevas se etiquetan como tales.

Ejemplo de diferencia: PDF propone disponibilidad configurable y un alcance de 60 días; README del prototipo usa una fecha límite de demostración (`30 de noviembre`) y horarios de muestra (martes-sábado, 10:00–20:00). **Esos valores del prototipo son datos demo, no políticas fijas de producción.**

Nombre: InkSlot es nombre provisional del sistema; Dodogio Studio es un texto de muestra identificado por README. Marca final y dirección real, pendientes de validación.
